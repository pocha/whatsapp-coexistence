app.post('/whatsapp-webhook', (req, res) => {
  for (const entry of req.body.entry) {
    for (const change of entry.changes) {
      if (change.field === 'smb_message_echoes') {
        for (const echo of change.value.message_echoes) {
          saveToConversationHistory(echo.to, { direction: 'out', from: 'human', ...echo });
          pauseAutoReplyFor(echo.to, { minutes: 30 });
        }
      } else if (change.field === 'messages') {
        // normal customer-initiated messages, handled as usual
      }
    }
  }
  res.sendStatus(200);
});

2. Send messages through the relay

        

          Once onboarded, send outgoing messages by calling our relay instead
          of Meta directly — same request body Meta's own
          /{phone-number-id}/messages endpoint takes, forwarded
          with your own access token:
        

        
POST /api/relay/<phone-number-id>/messages
Authorization: Bearer <your WhatsApp access token>
Content-Type: application/json

{
  "messaging_product": "whatsapp",
  "to": "<recipient>",
  "type": "text",
  "text": { "body": "Hello!" }
}

        

          We never store your token — it's forwarded per-request. Rate
          limiting and per-recipient serialization are upcoming.
        

      


      

        
3. Verify it worked

        

          Not a "send a test message" button — that only proves the relay
          works, which isn't in doubt. What actually matters:
        

        
    
          
  • Coexistence activated? Check the phone's WhatsApp Business App itself — Meta refreshes it automatically to show the number is now connected to the API. No message needed.
    • 
          
  • Is your echo handling correct? Send a message from that phone app and confirm your own server received an smb_message_echoes webhook for it. Only your real phone + your real server can prove this — nothing we send on your behalf would test it.
